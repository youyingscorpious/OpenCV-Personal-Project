## 1. 风险矩阵

| # | 风险 | 触发条件 | 影响 | 缓解 |
|---|---|---|---|---|
| **R1** | 固件在收到零速帧后仍上报 `RUNNING` | `0x10` 状态语义与预期不符 | 停稳确认超时 | 默认 `proceed`（告警后开窗），不新增失败点；可改 `fault` 收紧；根因在固件 |
| **R2** | `0x10` 状态帧断流 | 串口松动、固件异常 | 永远等不到停稳 | 2 s 上界 + `proceed`；同时父类会因遥测陈旧触发 `_fault` |
| **R3** | 轮速字段非编码器实测 | `motor_status_is_measured=false` | 停稳判据失效 | 闸门自动降级为 state-only，并 1 Hz 告警（D3） |
| **R4** | 颜色帧率不足导致锁不住 | 板端掉帧、网络丢包 | 等满 8 s 后 `FAULT` | 降 `route_color_vote_frames` 到 2 / 提 `vote_timeout_s`；本质是视觉链路问题 |
| **R5** | 闸门把"选错路"换成"卡死" | 停稳确认永不成立且未设上界 | 赛程卡死 | I4 不变量：2 s 上界 + 确定动作，自检场景 3 专门验证 |
| **R6** | 重复路口事件把车拉回路口，闸门又拦一次 | 固件锁存 event bit0 | 反复停 | 既有 `route_junction_ignore_s` 屏蔽；`_maneuver_done_once` 分支绕过闸门 |
| **R7** | 参数写错 YAML key | 写成 `voyager_gate:` | 闸门参数不生效，静默退化为默认值 | 04 文档 §1 有 `ros2 param list` 校验；默认值本身是安全的 |
| **R8** | 两个包同时运行 | 忘记关 `competition.launch.py` | 抢串口 / UDP 冲突 | 三处 README、launch 头注释、检查清单都写了 |
| **R9** | 模板副本与原包分叉 | 后续改了 `route_controller.py` | 行为不一致 | `competition_base.py` 头注释标明来源行；升级时整文件重拷 + 复查 §2 集成点 |
| **R10** | 行车时间变长 | 多出 ~0.4–0.6 s 停稳确认 + 0.3 s 投票 | 总成绩轻微变慢 | 换取"不选错支路 / 不打滑转向"；可把 `dwell` 降到 0.15、`vote_frames` 降到 2 收回一半 |

## 2. 为什么不做「真·下发触发」（方案 B）

需求原话是"**调用**色卡识别模块"。评估过让导航端真的向下位视觉发起调用，结论是不划算：

| 维度 | 方案 A（本方案） | 方案 B（板端下行触发） |
|---|---|---|
| 协议 | 零改动 | 新增下行命令语义（0x81/0x82 已有定义，但走 TCP 且当前 `ENABLE_TCP_SERVER=False`） |
| 板端代码 | 零改动 | `start_udp` 加 `bind:5000` + 主循环加 `poll_udp` + 重烧固件 |
| 导航端 | 闸门逻辑 | 同左，外加 UDP 发送与对端发现 |
| **能否真的关掉识别** | — | **不能**：关掉后目标列表停发，导航端 0.6 s 视觉超时（`vision_source_timeout_seconds`）会立刻 `FAULT`，车在循迹途中急停 |
| 因此实际可做 | — | 只能"帧照发、颜色压成 0" |
| 收益 | 因果顺序完全正确 | 省一点 K230 算力 |
| 风险 | 低（纯 PC 端逻辑） | 中（固件改动 + 新故障面） |

**关键点**：在推送模型下，"调用识别"能被观察到的唯一语义就是"**决定是否采信此刻的结果**"。
闸门实现的正是这个语义：停车 → 停稳 → 才开始用颜色 → 用完即关（`color_request=false`）。
因果顺序与真调用完全一致，而成本几乎为零。

若日后板端确要支持下行触发，只需把 `_gate_publish_request()` 从"发 ROS Bool"改成
"发一条 UDP 下行帧"，**闸门判定逻辑一行不改**——`/navigation/junction/color_request`
就是为此预留的挂钩。

## 3. 回退（三级）

| 级别 | 操作 | 影响面 | 何时用 |
|---|---|---|---|
| **L1 软回退** | `junction_gate_enabled:=false` | 关闸门，保留颜色投票（3 帧） | 现场发现闸门导致异常，但仍想去抖 |
| **L2 完全回退** | `junction_gate_enabled:=false` + `route_color_vote_frames:=1` | 与改造前逐字段一致 | 需要与旧版本逐帧对照 |
| **L3 物理回退** | 不启动 `voyager_gate`，改回 `ros2 launch robopioneers_competition competition.launch.py` | 完全回到原状态 | 赛前发现无法解决的问题 |

**L3 不需要删任何文件**：本包是新增目录，原件一个字节都没动，随时可以并行存在、随时弃用。

命令行写法：

```bash
# L1
ros2 launch voyager_gate voyager_gate.launch.py junction_gate_enabled:=false

# L2
ros2 launch voyager_gate voyager_gate.launch.py \
  junction_gate_enabled:=false route_color_vote_frames:=1

# L3
ros2 launch robopioneers_competition competition.launch.py
```

> L2 的等价性由离线自检场景 6 验证（`gate=false + vote_frames=1` → 单帧即锁定）。

## 4. 变更控制（对应规则 7.3.3-1）

- 所有闸门参数在**赛前**写入 `config/voyager_gate.yaml` 并固化；
- 计时开始后只读运行，不做 `ros2 param set`；
- 现场应急只能通过**重启并带 launch 参数**（等同于换配置），不得运行期改参。

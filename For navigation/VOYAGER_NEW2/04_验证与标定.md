## 2. 台架验证（无相机）

> ⚠️ `/navigation/start` 会检查 `motor_status`、`motor_chassis_status`、`servo_status_seen`
> 与视觉角色 `{1,2}`（[navigation_node.py:273](../robopioneers_navigation/robopioneers_navigation/navigation_node.py#L273)）。
> 只跑 PC 端、不接 MCU 时**无法开赛**，必须用半实物：
>
> * 方式 A：接真电机板 / 外设板，轮子架空；
> * 方式 B：`socat -d -d pty,raw,echo=0 pty,raw,echo=0` 造虚拟串口，再用一个脚本按
>   `docs/MCU_INTERFACE.md` 的格式周期回 `0x10` / `0x11` / 外设 `0x10`。

### 2.1 启动

```bash
ros2 launch voyager_gate voyager_gate.launch.py \
  start_vision_bridge:=true vision_source:=manual vision_module_path:=''
```

### 2.2 四条断言

**A. 行进中注入颜色必须被拒**

```bash
ros2 topic pub --once /vision_test/color std_msgs/msg/UInt8 "{data: 3}"
```

* 期望日志：`competition phase=COLOR_REJECTED: color=3 rejected: still line-following (I2)`
* 期望 `/navigation/competition/status` 中 **不出现** `ROUTE_COLOR_READY`

**B. 路口停车 → 停稳 → 开窗**

把 `0x10` 状态从 `RUNNING`/有速度 变成 `state=0, v=0/0`，触发路口事件（`0x11` event bit0 或 `0x10` state=6）。

* 期望相位序列：`JUNCTION_PARKED` → `JUNCTION_STOP_CONFIRMED` → `COLOR_WINDOW_OPEN`
* 期望 `ros2 topic echo /navigation/junction/color_request` 由 `false` 变 `true`

**C. 停稳后注入颜色才被采信，且需要连续 3 帧**

```bash
for i in 1 2 3; do
  ros2 topic pub --once /vision_test/color std_msgs/msg/UInt8 "{data: 1}"; sleep 0.12
done
```

* 前两帧**不应**出现 `ROUTE_COLOR_READY`
* 第三帧出现 `competition phase=ROUTE_COLOR_READY: color=1 confirmed by 3 frames at junction`
* 随后 `ROUTE_TURN_BEGIN` / `ROUTE_TURN_REACHED` / `ROUTE_FOLLOW`

**D. 抖动不锁定**

```bash
ros2 topic pub --once /vision_test/color std_msgs/msg/UInt8 "{data: 1}"
ros2 topic pub --once /vision_test/color std_msgs/msg/UInt8 "{data: 2}"
ros2 topic pub --once /vision_test/color std_msgs/msg/UInt8 "{data: 1}"
```

* 期望 **不出现** `ROUTE_COLOR_READY`，车保持零速
* 超过 `route_junction_color_wait_s`（默认 8 s）后进入 `FAULT`
  （这是既有行为：等不到稳定颜色就不走）

### 2.3 台架上的一个预期告警

台架若无 `0x10` 实测帧，会看到：

```
[warn] junction stop not confirmed in 2.0 s (no 0x10 status); opening color window anyway
```

这是 `junction_stop_confirm_timeout_action: proceed` 的设计行为（D1）。
**上车后应看到 `forced=False`**；若上车也一直 `forced=True`，说明 `0x10` 语义与预期不符，
先排查 §5，不要急着把参数调大。

## 3. 上车标定

### 3.1 先确认 `0x10` 速度字段是真实编码器值

```bash
ros2 topic echo /navigation/motor/chassis_status   # 看 heading_deg / distance_mm
ros2 topic echo /navigation/motor/state            # 状态字节
```

推车时应看到轮速随速度变化、停车后归零。若恒为 0 或不动 →
`motor_status_is_measured` 必须保持 `false`（原包会锁死 STOP 流程），闸门会降级为
state-only 判据并打印告警。

### 3.2 `junction_stop_confirm_*` 标定

| 现象 | 处理 |
|---|---|
| 日志一直 `forced=True`，且 `state=` 显示 `1 RUNNING` 但速度已归零 | 该固件在收到零速帧后仍报 RUNNING → 把 `junction_stop_confirm_timeout_action` 保持 `proceed`，或让固件在停车后回 `IDLE` |
| 车明显还在滑行就 `JUNCTION_STOP_CONFIRMED` | 增大 `junction_stop_confirm_samples`（→4/5）或 `dwell`（→0.4） |
| 停车后要等很久才开窗 | 减小 `dwell`（→0.15）；最小可到 `0.0` |
| 日志里 `v=` 显示非零但车看着停了 | `stopped_speed_threshold`（原包参数，默认 10 mm/s）偏小 → 适当增大到 20 |

### 3.3 `route_color_*` 标定

| 现象 | 处理 |
|---|---|
| 色卡看得清却锁不住 | 板端目标列表有丢帧 → `route_color_vote_frames` 降到 2，或 `vote_timeout_s` 增到 0.8 |
| 偶尔锁到错误颜色 | `route_color_vote_frames` 增到 4–5（10 Hz 下每 +1 帧 ≈ +0.1 s） |
| 开窗后迟迟等不到帧 | 检查 `/navigation/vision/target_list` 是否在刷；板端 `TARGET_RATE_HZ` 与网络 |
| 想彻底关掉闸门做对照 | `junction_gate_enabled:=false route_color_vote_frames:=1` |

### 3.4 信任遥测后收紧为硬门禁

标定完成、`forced=False` 稳定复现之后：

```yaml
junction_stop_confirm_timeout_action: fault
```

这样"没停稳就绝不转向"从**默认降级**变成**硬约束**。

## 4. 故障演练（赛前必做）

| 演练 | 操作 | 期望 |
|---|---|---|
| 视觉断流 | 开窗时拔掉板子网线 / 挡住镜头 | 车保持零速，8 s 后 `FAULT`，不发转向帧 |
| `0x10` 断流 | 拔电机板 UART | `_fault` + 急停帧；不会出现"以为停了就转" |
| 颜色乱跳 | 台架交替注入 1/2/1/2 | 不锁定，8 s 后 `FAULT` |
| 停稳确认卡住 | `junction_stop_confirm_timeout_action=fault` 且不喂 0x10 | 2 s 后 `FAULT`，车不动 |
| 一键回退 | `junction_gate_enabled:=false route_color_vote_frames:=1` | 行为与改造前一致 |

## 5. 日志判读速查

`/navigation/competition/status` 是 JSON：`{"phase","detail","route","state","turn_phase"}`。

| phase | 含义 | 下一步看什么 |
|---|---|---|
| `JUNCTION_PARKED` | 已进入路口，已发停车帧 | 等 `0x10` 零速帧 |
| `COLOR_REJECTED` | 有颜色帧被闸门丢弃 | 正常现象；若持续刷说明车没停稳或还没到路口 |
| `JUNCTION_STOP_CONFIRMED` | 停稳证据达标 | `forced=False` 为正常；`True` 见 §2.3 |
| `COLOR_WINDOW_OPEN` | 识别窗口已开 | 等 `ROUTE_COLOR_READY` |
| `ROUTE_COLOR_READY` | 颜色已投票锁定 | 随后应出现 `ROUTE_TURN_BEGIN` |
| `ROUTE_TURN_BEGIN` / `_REACHED` | 定角转向开始 / 到角 | 角度不对看 `route_angle_*_deg` 与 `route_heading_sign` |
| `ROUTE_FOLLOW` | 已进入支路循迹 | 完成 |
| `STOP_DELAY_BEGIN` | STOP 牌定距停车中（`stop_delay_mm>0`） | 与闸门无关 |

常见异常与既有排查项（`heading_deg` 不新鲜、`route_heading_sign` 反了、
路口事件锁存、`state=5 CMD_TIMEOUT` 等）见
[robopioneers_competition/操作手册.md 第 9 节](../robopioneers_competition/操作手册.md)，
本方案未改变这些机制。

# 第三版电机与外设固件接口

本说明按 `3rdversion_motor_pid` 与 `3rdversion_periph_pid` 源码校对。两个 MCU 各使用一条独立 USB-UART；ROS 节点只运行一个进程，同时轮询两条串口。

## 电控 UART 帧格式

两块板共同使用：

```text
AA 55 | LEN | CMD | DATA... | CRC_L CRC_H
```

- `LEN = 1 + DATA长度`，其中 1 字节是 CMD。
- CRC 为 CRC-16/MODBUS，初值 `0xFFFF`，覆盖 `LEN + CMD + DATA`，低字节先发。
- 多字节字段均为小端；串口为 USART2 PA2/PA3、115200、8N1。

## 电机板 `3rdversion_motor_new`

| 方向 | CMD | DATA | 说明 |
|---|---:|---|---|
| 导航→电机 | `0x00` | 空 | PING；运动期间至少 5 Hz，导航按 10 Hz 发送 |
| 导航→电机 | `0x01` | `<hh`：左轮目标 mm/s、右轮目标 mm/s | 手动差速速度；也用于暂停/STOP，零/零为停车 |
| 导航→电机 | `0x04` | 空 | 急停并锁存 |
| 导航→电机 | `0x05` | 空 | 清除急停、超时、路口或丢线状态 |
| 导航→电机 | `0x07` | 空或 `<h` 或 `<hh` | 启动本地循迹；导航发送 `<hh`：基础速度 mm/s、转向限幅 mm/s |
| 电机→导航 | `0x10` | `<hhB`：左轮实测 mm/s、右轮实测 mm/s、状态 | 上电立即发送，之后约每 100 ms |
| 电机→导航 | `0x11` | `B,h,h,i,h,B`：循迹位、误差、PID 修正、里程 mm、航向 x10、事件位 | 循迹遥测和路口/丢线事件 |

状态值：`0 IDLE`、`1 RUNNING`、`4 FAULT`、`5 CMD_TIMEOUT`、`6 JUNCTION`、`7 LINE_LOST`。速度由编码器换算得到。运动期间超过 300 ms 未收到有效命令/心跳会停车，因此导航在本地循迹模式运行时持续发送 `0x00 PING`。

## 外设/舵机板 `3rdversion_periph`

| 方向 | CMD | DATA | 说明 |
|---|---:|---|---|
| 导航→外设 | `0x02` | `uint8 id + int16 angle_x10` | 舵机角度命令，ID 1..3，角度 0..1800 |
| 导航→外设 | `0x03` | `uint8 action` | `1` 抓取、`2` 放置、`3` 复位 |
| 导航→外设 | `0x04` | 空 | 急停舵机动作序列 |
| 导航→外设 | `0x05` | 空 | 清除外设急停 |
| 导航→外设 | `0x06` | `uint8 device + uint8 value` | 外设输出：蜂鸣器或 LED |
| 外设→导航 | `0x10` | 8 字节：`<hhhBB` | 三个舵机角度 x10、状态、循迹位图 |

状态值：`0 IDLE`、`2 ARM_BUSY`、`3 ARM_DONE`、`4 FAULT`。外设帧中仍有循迹位图字段，但本导航包不再使用它闭环；循迹传感器建议只接电机板 PB12..PB15，循迹遥测通过电机 `0x11` 上报。外设状态约每 100 ms 回报一次。

电控固件中的机械臂舵机角度目前是占位参数，夹爪角度与动作顺序需要机械组/电控组实物标定后再用。

## 导航端循迹策略

新版电机板将 PB12..PB15 采样、增量 PID 和轮速闭环全部放在 MCU 本地。导航开始后发送一次 `0x07 LINE`（两个小端 `int16` 参数：基础速度、转向限幅），之后以 10 Hz 发送 `0x00 PING`。导航解析 `0x11` 以显示循迹数据并接收路口/丢线事件；不会再从舵机板读取循迹位，也不会周期性发送 `0x01 CHASSIS` 覆盖电机 PID。

全黑路口时，电机板会刹停并通过状态 6 / `0x11` event bit0 通知导航；丢线时状态 7 / event bit1。导航对路口保持停车并进入 `WAIT_ROUTE_MANEUVER`，对丢线进入故障停车。当前固件的 `0x07 LINE` 仅接受速度和转向限幅，没有红/黄/蓝分支参数，因此视觉颜色可被识别和记录，但不能据此自动选择赛道分支；要完成该动作，电控固件需新增并定义路线选择/转向命令，然后再接通导航状态机。视觉端仍负责颜色和 STOP 识别，导航包不启用相机驱动、图像处理或 Nav2。

## 视觉通信模块 `Communication_comm.py`

视觉帧使用 `AA 55 | DATA_LEN | SRC | CMD | SEQ | DATA | SUM8`，校验为 `DATA_LEN + SRC + CMD + SEQ + DATA` 所有字节和的低 8 位。该模块默认使用 UDP，一帧一个数据报。手机热点模式下，视觉板和 Ubuntu 均作为 STA 加入手机热点，视觉板应把 UDP 目的地址配置成 Ubuntu 热点网卡的 IP、目的端口配置为 `5000`；也可以用正确子网广播，但手机热点必须允许客户端互通。导航节点默认绑定 `0.0.0.0:5000`，可接收任意本机网卡收到的广播或单播。切换其他网络结构时，需使视觉端 UDP 目的地址与 Ubuntu 实际网段匹配。导航端也保留串口承载该帧格式的选项。

| CMD | 负载 | 导航端处理 |
|---:|---|---|
| `0x01` | 12 字节目标列表，最多两个颜色/距离/置信度目标和状态位 | 发布目标列表；SRC 1 的 `status.bit2` 为 STOP |
| `0x02` | 12 字节目标坐标 `<BBhhhhBB` | 发布坐标；`valid=0` 表示当前无坐标 |
| `0x03` | 8 字节心跳 `<BBHHBB` | 发布状态、FPS、错误计数、处理耗时和协议版本 |
| `0x04` | 4 字节错误 `<BBH` | 解析错误码、细节和累计计数并记录日志 |
| `0x05` | 9 字节版本信息，最后一字节为角色 | 校验 `role == SRC`，等待 SRC 1 与 SRC 2 握手 |

该通信模块会在视觉识别程序调用 API 时自动驱动版本/心跳，并将目标列表限频到 20 Hz；它没有解析导航端下发的启动或版本请求命令。因此导航包只等待来源版本帧并消费主动推送数据，不再向视觉端发送无效的启动命令。为兼容 1 Hz 心跳和短时 UDP 丢包，视觉整链路超时默认为 1.5 秒；相机 1 仍需持续调用目标列表 API（无目标时也发空列表），目标列表超时默认为 0.6 秒。

手机 AP、Ubuntu STA、视觉板 STA 的 IP 查看、UDP 目的地址设置和联调步骤见 [PHONE_HOTSPOT_SETUP.md](PHONE_HOTSPOT_SETUP.md)。

## 停车后舵机门控

视觉报告 STOP 后，导航向电机发送左右目标速度 0，切换到 `WAIT_MOTOR_STOP`。只有状态帧连续满足 `state=IDLE`、左右编码器速度低于阈值、连续样本数达标且持续时间达标，才通过外设 UART 依次发送抓取、放置、复位。每个舵机动作必须观察到 `ARM_BUSY` 后再收到 `ARM_DONE` 才会进入下一动作。停车确认或动作确认超时会进入 `FAULT`，不继续舵机序列。
